# CoralNPU 教学仓

这是一个「从零实现一颗 NPU」的课程。它把上游 `coralnpu` 仓库当作**规格来源与对照答案**，
而你要亲手写出其中的核心部件：从一颗 RV32I 单周期核心开始，一路走到向量核、矩阵引擎、
总线外设与端到端模型推理。

```bash
./learn doctor     # 第一步：检查环境（缺什么会告诉你装什么）
./learn list       # 看看 10 个阶段
./learn start L00  # 开始第一课
./learn check L00  # 跑检查器，看哪些作业还没过
```

## 从哪里开始

不确定自己的基础够不够，先花 5 分钟做诊断：

```bash
./learn diag        # 25 道题，告诉你缺哪一层（命令行 / 编译 / 数字逻辑 / Verilog / RISC-V）
./learn start P0    # 预备课（可跳过）：五个模块，每层都有可跑的小练习
```

诊断说「可以跳过」就直接开始 L00；说要补哪层，就去 P0 做对应模块（模块 A–E 与
诊断的五个层次一一对应）。P0 的目标不是学全，而是**能读懂 L00/L01 的作业说明**。

## 每节课有什么

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 基础知识.pdf | `lessons/<课>/pdf/基础知识.pdf` | 理论、术语、在线书籍与规范链接、自测题 |
| 作业说明.pdf | `lessons/<课>/pdf/作业说明.pdf` | 任务拆解、验收标准、调试方法、常见坑 |
| 骨架代码 | `lessons/<课>/rtl/` | 带 TODO 的 RTL，你只改这里 |
| 检查器 | `lessons/<课>/tests/checks.py` | 自动对拍，失败信息精确到某一条指令 |
| 参考实现 | `lessons/<课>/refs/` | 卡住时对照（`./learn unlock <课>`） |

## 课程设计原则

1. **只做加法**：上游的 RTL、Bazel 目标、文档、CI 全部保持原样，教学层都在 `course/` 里。
   你随时可以拿自己的实现和上游对照。
2. **规格先行**：每课先给接口契约（端口、时序、状态机），再让你写实现。
3. **三层验证**：Python 黄金模型（毫秒级）→ iverilog 仿真对拍（秒级）→ 上游 Bazel +
   cocotb 流程（分钟级，毕业用）。前三课只用前两层，2 核笔记本也能学。
4. **真实程序验收**：每课的完成标准是「上游仓库里真实存在的某个程序能在你的设计上跑通」，
   而不是「看起来写完了」。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `./learn doctor [--install]` | 环境自检 / 安装缺失组件 |
| `./learn list` | 阶段列表与完成度 |
| `./learn start L01` | 打开某一课的入口信息 |
| `./learn check L01 [--only 01] [--ref]` | 运行检查器（`--ref` 检查参考实现） |

| `./learn figs` | 重新生成插图 |

## 学习建议

* **不要先看参考实现**。检查器的失败信息已经足够具体，先自己定位 30 分钟。
* **每个 TODO 跑一次检查**，让失败位置从第 1 条指令慢慢往后退——这个「推进」的过程就是学习曲线。
* **写学习记录**：每课结束时记下「卡住你的那个 bug 和你是怎么定位的」，这比代码本身更值钱。
* **对照上游**：跑通之后再看 `hdl/chisel/` 与 `hdl/verilog/rvv/` 里的真实实现，你会发现
  上游多出来的部分（流水线、冒险、Cache、总线）都有明确的工程理由。
